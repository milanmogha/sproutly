[FEE] FEE MANAGEMENT — spec-compliance audit (2026-07-10)
      Backend fee domain was already fully built (structures CRUD, generate,
      payments, receipts, reports). The ADMIN APP was missing the two creation
      flows entirely — audit found ~40% of the backend was surfaced.
      DID (v1.1.2): rebuilt AdminFeesScreen into 3 tabs matching the spec —
        · Structures tab: list + create/edit/delete fee-structure templates
          (name, frequency, academic year, dynamic components w/ live total,
          due day). AdminApi.listStructures/saveStructure/deleteStructure +
          FeeStructureModel.
        · Generate tab: pick structure + class + period + due date →
          POST /fees/invoices/generate; shows created/skipped counts.
        · Invoices tab: summary cards + All/Unpaid/Paid filter + invoice
          breakdown sheet with line items and a REAL record-payment form —
          custom amount (partial payments), method picker (cash/card/upi/
          bank_transfer/cheque), optional note (was full-cash-only before).
      STILL OPEN (from the audit, ranked):
        1. Overdue status never set — no code path or scheduler flips
           past-due pending/partial invoices to 'overdue'; the chips are dead.
           Fix: a scheduled job OR compute-on-read in findInvoices/dues.
        2. Receipt generated but never shown — add getReceipt/invoicePayments
           calls + a receipt / payment-history view after recording.
        3. Collection report drops byMethod + no date range (models +
           admin_api.collectionSummary) — parse byMethod, pass from/to, render.
        4. Invoice list caps at limit:50 and ignores server ?status — paginate
           / raise limit; push the filter server-side for big schools.
        5. SECURITY: GET /fees/students/:id/invoices and /fees/dues have no
           parent↔child ownership check (IDOR) — a parent could read another
           student's invoices in the same school. Add a guardian check.
        6. Invoice/payment/receipt numbering is read-max-then-increment (no
           atomic counter) — can duplicate under concurrent requests → E11000.
        7. Structure dueDayOfMonth is stored but unused — generate applies one
           flat dueDate to all; could derive per-period due dates from it.
